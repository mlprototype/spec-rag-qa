# RAG・検索システム用語集

RAG（Retrieval-Augmented Generation：検索拡張生成）システムにおいて、「検索をいかに賢く、正確に行うか」に関わる重要な5つの用語の解説です。

## 1. FAISS（フェイス）＝ 「意味」で探す司書さん（ベクトル検索）
*   **正式名称:** Facebook AI Similarity Search
*   **役割:** 文章の「意味」を理解して、似ている情報を探してくる仕組みです。
*   **例え:** 図書館の司書さんに「犬の飼い方について知りたい」と聞くようなものです。司書さんは「犬」という言葉が入っていなくても、「子犬のしつけ」や「ペットの食事」といった**意味的に関連する本**を見つけてくれます。
*   **特徴:** 「表記揺れ（例：スマホとスマートフォン）」に強く、ふわっとした質問でも意図を汲み取って探せます。

## 2. BM25（ビーエム・ニジュウゴ）＝ 「キーワード」で探す索引（キーワード検索）
*   **役割:** 昔ながらの検索エンジンのように、指定した「キーワード」が文章の中にどれくらい含まれているかで探す仕組みです。
*   **例え:** 本の巻末にある「索引（インデックス）」を使って探すようなものです。「犬」で探せば「犬」という単語が含まれるページを確実に見つけますが、「子犬」と書かれているページは見逃してしまいます。
*   **特徴:** 固有名詞、品番、社員番号など、**「一言一句間違えずにその言葉が入っている文章」**を探すのが得意です。

## 3. ExactMatchBoost（イグザクト・マッチ・ブースト）＝ 「完全一致ボーナス」
*   **役割:** 検索キーワードと「完全に一致」する言葉が含まれている文書に対して、検索順位のスコア（点数）を特別に加算（ブースト）する仕組みです。
*   **理由:** FAISS（意味検索）だけだと、AIが「似ている」と勘違いして、微妙に違う品番の資料を上位に出してしまうことがあります。そこで、「ユーザーが入力したキーワードがそのまま入っている資料は、絶対に重要だから点数を高くしよう」というルールを追加するのです。

## 4. RRF（アール・アール・エフ）＝ 「順位を公平に合体させる計算式」
*   **正式名称:** Reciprocal Rank Fusion
*   **役割:** 複数の異なる検索方法（例えば FAISS と BM25）の結果を、上手く1つにまとめる（ランキングし直す）ための計算方法です。
*   **理由:** FAISSは「意味の近さ」で点数を出し、BM25は「キーワードの出現回数」で点数を出します。点数の基準が全く違うため、単純に足し算できません。
*   **仕組み:** 「点数」ではなく**「順位」**に注目します。「FAISSのランキングで1位の資料」と「BM25のランキングで1位の資料」に高いスコアを与え、両方で上位に入っている資料はさらに上位になるように計算します。

## 5. HybridRetriever（ハイブリッド・レトリーバー）＝ 「すべてを組み合わせた最強の検索係」
*   **役割:** これまで説明したものをすべて組み合わせて、検索を行うプログラムのことです。
*   **全体像:**
    1.  ユーザーが質問する。
    2.  **FAISS** が「意味」でトップ10の資料を探す。
    3.  同時に **BM25** が「キーワード」でトップ10の資料を探す。
    4.  （必要に応じて **ExactMatchBoost** でキーワード完全一致の資料の点数を上げる）
    5.  **RRF** の計算式を使って、2つのランキングを公平に合体させ、最終的なトップ10を決める。
*   **なぜこれが必要か:** 「意味」だけでも、「キーワード」だけでも完璧な検索はできないからです。ハイブリッドにすることで、**「ニュアンスも理解しつつ、専門用語や品番も正確に見つける」**という、実用的なAIシステム（RAG）に不可欠な高い検索精度を実現できます。

## 6. Ground Truth（グラウンド・トゥルース） ＝ 「絶対に正しい模範解答」
*   **役割:** AIの回答や検索結果が合っているかを判断するための、人間が用意した「絶対的な正解」のことです。
*   **例え:** 学校のテストの「先生が持っている解答用紙」です。
*   **なぜ必要か:** これがないと、AIがもっともらしい嘘をついたときに、それが「嘘だ」とシステム的に採点できないため、評価において一番の土台になります。

## 7. Recall @ K（リコール・アット・ケー） ＝ 「上位○件の中に、正解の資料が入っている確率」
*   **読み方:** リコール・アット・ケー（Kには数字が入ります。例：Recall@5、Recall@10）
*   **役割:** 検索エンジンが探してきた上位K件の資料の中に、Ground Truth（正解の資料）がちゃんと含まれている割合です。
*   **例え:** 探偵に「犯人の手がかりを5つ（K=5）集めてきて」と頼んだとき、その5つの中に「本当の決定的な証拠」が含まれていた確率です。
*   **特徴:** RAGにおいては、「AIに読ませるトップ5の資料の中に正解があるか」が超重要なので、最もよく使われる検索評価の指標です。

## 8. MRR（エム・アール・アール） ＝ 「正解がどれだけ『早く（上位に）』出てきたかの点数」
*   **正式名称:** Mean Reciprocal Rank（平均逆順位）
*   **役割:** 検索結果の中で、「一番最初の正解」が何位に出てきたかを評価する計算式です。
*   **計算方法:** 1位で出たら「1点」、2位なら「0.5点（1/2）」、3位なら「0.33点（1/3）」...と、順位が下がるほど点数が下がります。
*   **なぜ必要か:** Recallが「5件の中に入っていればOK」という基準なのに対し、MRRは**「やっぱり1位に正解が出てくるのが一番優秀だよね」**という、検索の順位の質を厳しく評価します。

## 9. FailureRate（フェイラー・レート） ＝ 「失敗率（お手上げ率）」
*   **役割:** システムがエラーを起こしたり、「分かりません」と回答したり、見当違いな動きをしてしまったりした割合です。
*   **意味:** 全体の質問のうち、何％の質問でシステムが正常な回答を返せなかったかを示します。

## 10. Latency（レイテンシ） ＝ 「待ち時間（レスポンスの速さ）」
*   **役割:** ユーザーが「質問ボタン」を押してから、AIが「回答を返し始める（または返し終わる）」までの時間です。
*   **例え:** レストランで注文してから料理が出てくるまでの時間です。
*   **特徴:** どんなに賢いAIでも、待ち時間が長すぎると使われないため、精度とレイテンシのバランスが重要です。

## 11. Baseline（ベースライン） ＝ 「基準となる比較対象（現状の実力）」
*   **役割:** 新しい仕組み（ハイブリッド検索など）を試すときに、「比べる対象」とする、一番シンプルで基本的なシステムのことです。
*   **例え:** 筋トレの成果を測るための「ダイエット前の体重」です。
*   **使い方:** 「ただのBM25検索（Baseline）」と「新しいシステム」を戦わせて、どれくらい点数が良くなったかを確認します。

## 12. SLO（エス・エル・オー） ＝ 「死守すべきサービスの品質目標」
*   **正式名称:** Service Level Objective
*   **役割:** 開発チームが「ユーザーのために、最低限このレベルの品質は約束します」と決めた目標値のことです。
*   **例:** 「LatencyのSLOは3秒以内」「Recall@5のSLOは80%以上」など。
*   **なぜ必要か:** 開発のゴールテープとして機能し、本番リリース可能かどうかの判断基準となります。

## 13. Dense Search（密な検索 / ベクトル検索） -> FAISS
*   **役割:** 文章を「数値の塊（ベクトル）」に変換し、空間上の距離が近い（＝意味が似ている）ものを探す検索方法です。
*   **代表例:** FAISS（先述）、Pinecone、Weaviateなど。
*   **特徴:** 「PC」と「パソコン」のような表記揺れに強く、文章の「文脈」や「ニュアンス」を汲み取るのが得意です。一方で、特定の型番や専門用語など「一言一句の完全一致」を見つけるのはやや苦手です。

## 14. Sparse Search（疎な検索 / キーワード検索）-> BM25
*   **役割:** 文章の中に「指定したキーワードが含まれているかどうか」を数え上げて探す、昔ながらの検索方法です。
*   **代表例:** BM25（先述）、Elasticsearch（のデフォルト設定）など。
*   **特徴:** 固有名詞、品番、社員番号など、特定の一致が求められる検索に非常に強いです。一方で、「走る」で検索した時に「ダッシュする」などの同義語を拾うことはできません。

## 15. Hybrid Search（ハイブリッド検索）
*   **役割:** Dense Search（意味検索）と Sparse Search（キーワード検索）の両方を同時に実行し、その結果を組み合わせて表示する検索方法です。
*   **仕組み:** 一般的に「RRF（先述）」などの計算式を使って、Denseで上位のものとSparseで上位のものの順位をうまく合体させます。
*   **なぜ必要か:** AIシステム（RAG）において、ユーザーのふわっとした質問（意味）を拾いつつ、社内特有の専門用語や品番（キーワード）も正確に捉えるためには、どちらか片方だけでは不十分であり、両方の「いいとこ取り」をする必要があるからです。

## 継続的評価アーキテクチャ（二層CI/CDサイクル）

RAGシステムの検索品質を維持・向上させるために、「守り」と「攻め」の責務を分離した2つの自動化サイクルの総称です。これにより、開発スピードを落とさずに品質を保証します。

### 16. PR Gate（守りの機構）
*   **役割:** 開発者がコードを変更（Pull Request）した際に、**「既存の検索品質を壊していないか（デグレードしていないか）」**を検証する門番です。
*   **特徴:**
    *   **フェイルファスト:** 失敗したらすぐ停止し、無駄な計算（LLMのAPIコストなど）を省きます。
    *   **オフライン実行:** APIを使わずローカルの計算だけで完結させることで、外部要因（ネットワークやAPIの不調）によるテストのブレや遅延を防ぎます。
    *   **SLOのラチェット（歯止め）:** 「過去の最高スコア（ベースライン）」と比較して品質が下回っていないかをチェックし、下回っていればマージをブロック（阻止）します。

### 17. Nightly 探索 / Grid Search（攻めの機構）
*   **役割:** 夜間（Nightly）などの定期的なタイミングで、**「今よりもっと検索精度が良くなる設定（ハイパーパラメータ）はないか」**を総当たりで探し出すシステムです。
*   **特徴:**
    *   **計算コストを許容:** PR Gateでは重すぎて実行できない、数十パターンの組み合わせの評価や、LLMを使った大規模なテスト（ドリフト検知）を時間をかけて行います。
    *   **非破壊:** このテストが失敗したりスコアが悪かったりしても、開発を止めることはありません。見つかった「新しい最適解」は候補として蓄積され、最終的に人間が採用を判断します。

  なぜこの2つを分離しているのか？（責務分離の意図）

  もしPRごとにGrid Search（探索）や重いLLM評価を走らせてしまうと、CIの実行時間が長くなりすぎて開発スピード（アジリティ）が著しく低下してしまいます。

  そのため、
   * PR Gate では「絶対に品質を下げないための高速なテスト」だけを行い、開発のスピードを止めない。
   * Nightly 探索 では「時間をかけてもいいから、より良い設定の探索と網羅的な品質チェック」を裏側で回し続ける。

  という役割分担（2層のCIサイクル）によって、安全性と進化の両立を図るアーキテクチャになっています。
